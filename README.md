## 我在项目的实现过程中有没有遇到什么典型的困难？我是怎么最终达成困难的解决的？
有的喵，兄弟，有的喵。  
在测试的时候，有一个让我炸毛的bug。  
我开始运行程序之后，有些时候程序会卡死。我开始尝试减小测试数据量，结果发现减小了数据量以后代码又能跑起来了。  
这个时候我想起了一件事情：我的渲染算法是递归的，我记得不管是我还是AI都没有写数据缓存的代码。  
修读C++课程的时候，老师现场编写了一段递归计算斐波那契数列第n项的代码，刻意没有写缓存代码，结果在n = 13左右的时候程序计算就明显吃力了。  
于是我问了一下AI，发现这个代码渲染算法的时间复杂度大概在 O(4^n) 的数量级喵。算法在数据量增加的时候，计算所花费的时间是成指数增长的喵。
在编写了有关位置的缓存实现后，渲染时间显著加快，时间复杂度降到 O(n) 级别，输出成品简历的时间在6.5s左右喵。

## 功能特性
- 简历模板生成
  - 创建一个210*297的root:LayoutObject对象占满整个页面。后续的模板都挂到root以及其子对象的子对象下。
  - 在root及其子对象上通过挂载各种子模板实现排版控制。由于TextObject、ImageObject、RectangleObject都继承自LayoutObject，
    所以所有子模版生成函数，都有一个参数是LayoutObject类型的，返回的都是已经挂载好子模版的LayoutObject对象。

  在调用模板生成函数的时候传入一个LayoutObject对象，就可以实现在该对象下挂载子模版。
  在模板构建的时候按照需要调用不同的模板生成函数，就可以生成千变万化的模板。

- 简历数据填充
  - LayoutObject类提供了find_by_name()方法，允许通过LayoutObject的name字段匹配来寻找LayoutObject对象。
  - 调用一个对象的find_by_name()方法，就可以在这个对象及其子对象中寻找一个名称相符的LayoutObject对象或者其派生类对象。
  - 程序提供一个快速装填方法，用于给定一组数据，按模板填充数据。
 
- 将简历渲染成pdf并保存
  - fpdf2提供了一些向PDF文件输出的API，通过每一个派生类不同的render()方法，调用不同的API，就可以实现向PDF上渲染不同的内容。
  - 渲染算法采用递归遍历。一个LayoutObject类及其派生类的对象总是会在自己的render()被调用的时候先完成自己的渲染步骤再递归调用每一个子对象的render()方法，
    等待所有子对象的render()方法返回以后返回。
  - 每一个Resume类的实例都可以生成一份以{名字}-{意向岗位}-{意向公司}.pdf为文件名的文件，保存在传入该类的Generate()方法中的参数output_dir所指定的路径下。

## 如何运行？
我在项目的BlankResumeTemplateWithTestData.py中留有一份填有示例数据的模板喵。
可以打开该文件，将不想填写的数据行注释或删除掉，按F5运行等待结果喵。
也可以基于该文件填写自己的简历数据按F5运行渲染保存自己的简历喵。
